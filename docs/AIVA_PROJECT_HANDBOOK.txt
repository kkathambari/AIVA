1. EXECUTIVE PROJECT SUMMARY & MOTIVATION
================================================================================

1.1 THE ACADEMIC VIVA VOCE CHALLENGE
In higher education engineering and computer science curricula, the oral defense
(viva voce) is the gold standard for verifying that a student genuinely designed,
authored, and understood their technical dissertation. However, traditional
human-led oral examinations suffer from three critical institutional pathologies:

1. EVALUATOR SUBJECTIVITY & FATIGUE:
   Faculty examiners frequently conduct 10 to 15 viva sessions sequentially in a
   single day. Severe cognitive fatigue sets in, leading to subjective grading,
   inconsistent scoring criteria, and arbitrary grade inflation or deflation.

2. PROHIBITIVE DISSERTATION VOLUME:
   Undergraduate and postgraduate dissertations span 60 to 150+ pages. Because
   examiners lack the time to thoroughly read every technical nuance, they often
   rely on generic question pools (e.g., "What are the limitations of your work?"),
   failing to test deep project-specific architectural implementation details.

3. LOCAL SEMANTIC TRAPPING & STATIC RIGIDITY:
   In dialogue-based oral exams, follow-up questions often latch onto whatever
   specific keyword the student just uttered. This causes conversational
   "local semantic trapping" where 40% of the interview is spent circling
   around a single peripheral library (e.g., Docker configuration) while core
   theoretical concepts, algorithms, and architectural trade-offs remain
   completely unassessed.

1.2 AIVA SOLUTION & CORE VALUE PROPOSITION
The Adaptive Multi-Agent Viva Assessment Framework (AIVA) is an autonomous,
research-grade artificial intelligence examination platform designed to solve
these challenges. AIVA ingests the candidate's actual report (PDF, DOCX, PPTX),
extracts an interactive 3D Knowledge Graph of project concepts and relationships,
indexes text chunks using Hybrid Retrieval (Dense Semantic Vector Search + Okapi
BM25 Lexical Search fused via Reciprocal Rank Fusion), and deploys an explainable
panel of four distinct academic examiner personas.

During the viva, AIVA dynamically navigates the project syllabus using a novel
Unresolved Concept Selection (UCS) algorithm that avoids conversational trapping,
adapts question difficulty in real time via Reinforcement Learning (Gymnasium
MDP + DQN), accepts multimodal voice/text answers, and produces post-examination
diagnostic analytics detailing concept coverage, identified knowledge gaps, and
rubric-calibrated readiness.

1.3 KEY ARCHITECTURAL PILLARS
- STRICT GROUNDING (ZERO HALLUCINATION):
  Every single question generated is strictly anchored to chunks retrieved
  directly from the candidate's submitted document.
- TOPOLOGICAL PREREQUISITE AWARENESS:
  Concepts are sequenced such that foundational dependencies (e.g., Matrix
  Multiplication, Feature Extraction) are assessed before dependent modules
  (e.g., Convolutional Layers, Transformer Heads).
- REINFORCEMENT LEARNING DIFFICULTY CALIBRATION:
  Question complexity moves along five discrete cognitive levels (0 to 4)
  to keep the student in the "Zone of Proximal Development" (Target Score: 0.70).
- MULTI-AGENT PERSONA SPECIALIZATION:
  Instead of a generic chatbot, AIVA emulates an authentic examination committee:
  The Professor, The Industry Expert, The Critic, and The General Examiner.
- EXPLAINABLE DIAGNOSTICS:
  Examiners and students receive mathematical diagnostic reports with TF-IDF
  concept coverage radar, XGBoost weakness indicators, and rubric breakdowns.

3.2 UNRESOLVED CONCEPT SELECTION (UCS) ALGORITHM
--------------------------------------------------------------------------------
The primary algorithmic contribution of AIVA is the Unresolved Concept
Selection (UCS) algorithm. Standard conversational agents generate follow-up
questions based on the student's immediately preceding utterance, which causes
them to become trapped in localized conceptual clusters.

To prevent this, UCS computes an objective priority score S(c) for every
concept node c in the project Knowledge Graph:

    S(c) = w_1 * G_c + w_2 * P_c + w_3 * U_c - w_4 * R_c

Where the weights satisfy:
    w_1 + w_2 + w_3 + w_4 = 1.00
    w_1 = 0.35 (Knowledge Gap Weight)
    w_2 = 0.25 (Prerequisite Topological Centrality Weight)
    w_3 = 0.25 (Epistemic Mastery Uncertainty Weight)
    w_4 = 0.15 (Recency & Frequency Redundancy Penalty)

Mathematical Definitions of Components:

1. G_c (Estimated Knowledge Gap):
   Quantifies the extent to which concept c has not been mastered:
   - If concept c is unassessed:
     G_c = 1.0
   - If concept c has been assessed across n attempts with scores s_1, ..., s_n:
     G_c = max(0.0, 1.0 - mean(s_c))

2. P_c (Prerequisite Topological Importance):
   Measures structural centrality in the project prerequisite DAG:
   - Concepts that are foundational prerequisites for multiple downstream modules
     must be verified first:
     P_c = (out_degree(c) + 0.5 * in_degree(c)) / max_degree_normalization

3. U_c (Epistemic Mastery Uncertainty):
   Measures confidence in the candidate's current estimated mastery:
   - If unassessed:
     U_c = 1.0
   - If assessed:
     U_c = (1.0 / (1.0 + attempts_c)) + 0.5 * (1.0 - 2.0 * |mean_score_c - 0.5|)
   - Uncertainty is maximized when attempts are low or when scores hover near 0.5.

4. R_c (Recency & Frequency Redundancy Penalty):
   Penalizes circular re-examination of recently asked concepts:
     R_c = (attempts_c / (current_turn + 1.0)) + (0.5 if last_turn == current_turn - 1 else 0.0)

3.3 ADAPTIVE DIFFICULTY CONTROL VIA REINFORCEMENT LEARNING
--------------------------------------------------------------------------------
AIVA models the examination as a Markov Decision Process (MDP) to adapt question
difficulty dynamically:

1. State Space (S_t in R^2 or R^3):
   - Current Difficulty Level: D_t in {0, 1, 2, 3, 4} (normalized by 4.0)
   - Last Answer Score: Score_t in [0.0, 1.0]
   - Historical Moving Average: Sliding mean of past 3 answer scores

2. Action Space (A = {0, 1, 2}):
   - a = 0 : Decrease difficulty by 1 level (minimum: 0)
   - a = 1 : Maintain current difficulty level
   - a = 2 : Increase difficulty by 1 level (maximum: 4)

3. Difficulty Level Semantics:
   - Level 0 (Fundamentals): Definitions, syntax, high-level purpose
   - Level 1 (Easy): Standard API calls, baseline workflows
   - Level 2 (Medium): System interactions, design patterns, modular architecture
   - Level 3 (Hard): Concurrency, latency optimization, fault tolerance, scaling
   - Level 4 (Research Level): Source internals, mathematical proofs, edge cases

4. Flow Channel / Zone of Proximal Development (ZPD) Reward Function:
   The learning goal is to keep candidate response scores within [0.40, 0.70]:
   - If Score_t < 0.40 (Candidate in Anxiety/Struggle Zone):
     Action 0 (Decrease) -> Reward = +1.0
     Action 1 or 2 (Keep/Inc) -> Reward = -1.0
   - If Score_t > 0.70 (Candidate in Boredom/Trivial Zone):
     Action 2 (Increase) -> Reward = +1.0
     Action 0 or 1 (Dec/Keep) -> Reward = -1.0
   - If 0.40 <= Score_t <= 0.70 (Optimal Flow Channel):
     Action 1 (Maintain) -> Reward = +1.0
     Action 0 or 2 (Disrupt) -> Reward = -0.5

3.4 FOUR-DIMENSIONAL RUBRIC-BASED ANSWER EVALUATION
--------------------------------------------------------------------------------
Rather than subjective letter grading, AIVA evaluates candidate responses against
a 4-dimensional objective rubric derived from academic oral defense criteria:

    Composite Score = 0.35 * Correctness +
                      0.25 * Completeness +
                      0.20 * Evidence Alignment +
                      0.20 * Reasoning Depth

Dimension Definitions:
1. CORRECTNESS (35%):
   Technical accuracy of the facts, formulas, and mechanisms articulated.
2. COMPLETENESS (25%):
   The degree to which all key sub-facets of the examiner's inquiry were addressed.
3. EVIDENCE ALIGNMENT (20%):
   Consistency with the architectural claims and facts in the project report.
4. REASONING DEPTH (20%):
   The candidate's ability to explain "why" architectural choices were made and
   justify trade-offs rather than simply reciting definitions.

3.5 MULTI-AGENT DIALOGUE & PERSONA DIFFERENTIATION
--------------------------------------------------------------------------------
AIVA models four distinct academic personas coordinated via LangGraph:
- The Professor: Focuses on algorithmic rigor, math, Big-O complexity.
- The Industry Expert: Focuses on deployment, Docker, Redis, APIs, CI/CD, scalability.
- The Critic: Focuses on bottlenecks, failure points, security, trade-offs.
- The General Examiner: Focuses on system architecture, pipelines, overview.

Turn Fairness & Diversity Metric (Shannon Entropy):
To ensure all examiners participate fairly, persona turn distribution is
monitored via Shannon Entropy H:

    H = - sum_{i=1}^{M} p_i * log_2(p_i)

Where M = 4 personas, and maximum entropy is log_2(4) = 2.000 bits (perfect balance).

--------------------------------------------------------------------------------
3.6 HYBRID INFORMATION RETRIEVAL & RECIPROCAL RANK FUSION (RRF)
--------------------------------------------------------------------------------
Technical reports contain both conceptual discussions (which vector search
excels at) and specific variable names, constants, and function calls (which
lexical search excels at).

AIVA executes a two-stage hybrid retrieval strategy:
1. Dense Retrieval: Computes 3072-dimensional embeddings via Gemini Embedding 2
   and retrieves nearest neighbors from ChromaDB using cosine distance.
2. Sparse Retrieval: Okapi BM25 searches an inverted index of normalized tokens.
3. Reciprocal Rank Fusion (RRF): Merges the two ranked lists:

    RRF_Score(d) = sum_{m in {Dense, BM25}} 1.0 / (k + r_m(d))

Where r_m(d) is the 1-based rank position of chunk d in retriever m, and k = 60
is the standard smoothing constant preventing rank outliers from dominating.

   - Click on any concept node (e.g., "ChromaDB") to inspect its type, degree,
     prerequisites, and connected components.

   - Text: Type the detailed answer into the response text area and click Send.
5. Behind the scenes:
   - The answer is evaluated across Correctness, Completeness, Evidence, Depth.
   - The UCS engine recalculates knowledge gaps and picks the next optimal concept.
   - The Adaptive Engine steps difficulty (e.g., Level 1 -> Level 2).
   - The LangGraph Router selects the next examiner (e.g., The Industry Expert).
   - The question is grounded in retrieved report chunks and spoken via TTS.

10. TROUBLESHOOTING, DIAGNOSTICS & FAQS
================================================================================

10.1 PORT & NETWORK BINDING ISSUES
- Symptom: `ERROR: [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8000)`
- Cause: An existing instance of Python or Uvicorn is already occupying port 8000.
- Resolution (Windows PowerShell):
  ```powershell
  # Find process occupying port 8000
  netstat -ano | findstr :8000
  # Terminate the process by PID
  taskkill /PID <PID_NUMBER> /F
  ```
- Re-run `python -m uvicorn main:app --port 8000 --reload`.

10.2 AUDIO MIME & BROWSER FALLBACK TROUBLESHOOTING
- Symptom: Audio recordings fail to transcribe on Safari or older Chrome browsers.
- Cause: Different browsers encode MediaRecorder streams in varying codecs
  (`audio/webm;codecs=opus`, `audio/ogg`, or `audio/mp4`).
- Resolution: AIVA's `core/voice_engine.py` includes automatic format sniffing.
  If native local audio parsers fail, the raw audio stream is redirected to
  the Gemini Multimodal Audio API, which natively processes all standard
  audio container formats. Ensure your `GEMINI_API_KEY` is valid.

10.3 GEMINI API KEY & RATE LIMIT DIAGNOSTICS
- Symptom: `429 ResourceExhausted: Quota exceeded for quota metric 'Queries'`.
- Cause: Using a free-tier Gemini API key with low rate limits under rapid requests.
- Resolution:
  1. Add exponential backoff delays between calls (built into AIVA's client).
  2. For zero-quota offline development, all unit test suites in `tests/` use
     mocked deterministic responses, allowing 100% offline testing:
     `python tests/test_deterministic_end_to_end.py`

10.4 MODEL DESERIALIZATION & VIRTUAL ENVIRONMENT ISSUES
- Symptom: `ModuleNotFoundError: No module named 'gymnasium'` or `'xgboost'`.
- Cause: Python commands executed outside the active virtual environment.
- Resolution: Always ensure your virtual environment prompt is active:
  ```powershell
  cd e:\AIVA\AIVA_backend
  .\venv\Scripts\Activate.ps1
  pip install -r requirements.txt
  ```
